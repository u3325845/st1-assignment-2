The five limitations between the output of task 1 and task 1 enhanced are :

1. Possible conflicts in booking:
In both Task 1 and Task 1 Enhanced, there is no function to stop patients from booking the same practitioner at the same time, and no function to warn of any scheduling conflict.

2. Updates or changes in schedule:
There is no function or code for any update to schedule changes, or for cancellation, in the code. So if anyone wants to change their appointment time or cancel it, the code has nothing to help with that.

3. Error handling:
Only the empty patient name is checked, through one of the functions. The practitioner_name or appointment_time being empty or invalid are not checked.

4. Patient number allocation:
There is no unique identifying number given to patients with similar or the same names, to make appointment scheduling easier and reduce confusion.

5. Lacks input validation:
There is no function where the data type has been specified for checking for example, the receptionist can put the time of appointment under patient_name and vice versa, and no warning will be generated.
